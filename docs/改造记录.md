# 改造记录

这份文档记录的是**为什么**这么写。以后回头看，或者换电脑重装时，先读它。

## 起点：一个说不清的"卡"

2026-10-30 早上，用 Codex 生图时觉得"很卡"。最初的判断是"代理通道整体卡了"，但实测推翻了这个假设：

| 项目 | 经代理（香港） | 直连对照 |
|---|---|---|
| 下行 | 9.55 MB/s | 4.15 MB/s |
| **上行** | **85 KB/s** | **821 KB/s** |
| 延迟 | 22–29 ms | — |

下行很快、延迟很低，**只有上行被压到 1 Mbps 以下**。这就是第一层认知：**延迟正常不等于线路正常，对上传型负载来说，上行才是命门。**

## 排查过程（按发现顺序）

### 1. 走错节点：以为是香港08，其实是新加坡01

Clash 处于 `global` 模式，真正生效的是 `GLOBAL` 组，它选的是新加坡01。香港08 只是 `Proxies` 组里的"名义值"——而 `Proxies` 当时选的还是个**伪节点**（机场把「当前流量：121.55G / 400.00G」也做成了一个 AnyTLS 条目塞进组里，选中就等于把流量发给一个假地址）。

教训：**看板不能只显示"你选中了谁"，要显示"流量实际走在谁身上"。**

### 2. 香港整批节点上行都被限死

逐个实测香港 01–10（2026-10-30 白天）：

```
香港 01  99 KB/s     香港 06  105 KB/s
香港 02 117 KB/s     香港 07  142 KB/s
香港 03 112 KB/s     香港 08  131 KB/s
香港 04 157 KB/s     香港 09  139 KB/s
香港 05 117 KB/s     香港 10  118 KB/s
```

不是个别节点差，是**整批入口的上行被机场硬性限速**。当晚复测，香港回到 400–440 KB/s，但日本是 2000–2830 KB/s —— **所以节点排名会随机场调度变化，一次测完不能永久固定。**

### 3. 真正的机制：AnyTLS 单隧道的队头阻塞

这是最关键的认知。AnyTLS 是单连接多路复用，Clash 里看到的是：

```
GLOBAL > 香港06     承载 28 个请求
```

28 个不同域名的请求跑在同一条 TCP 上。**一个上传卡住，整条隧道上所有请求一起排队**。所以症状不是"某个请求慢"，而是"Codex 界面整片卡死"。

### 4. 客户端自己也很重

同一时刻：

```
codex 主进程        989 MB
codex 系进程合计   1816 MB   （次日 2824 MB，第三天 2933 MB）
空闲时 CPU 增量     0.0s / 6s
```

网络空闲、TTFB 0.42s / HTTP 200，但进程占 1.8–2.9 GB。**"卡"有两个独立来源：网络和客户端，必须分开判。**

### 5. 改的配置会被 Clash Verge 改回去

这是最有挫败感的一段。改文件 → 生效 → 几小时后回滚。

日志实证：

```
10:31:41  Proxies 组被改动，已纠正 → 日本 05
10:32:49  Proxies 组被改动，已纠正 → 日本 05
10:33:50  Proxies 组被改动，已纠正 → 日本 05
10:34:50  Proxies 组被改动，已纠正 → 日本 05
```

每分钟被改一次，守护每分钟拉回来 —— 拉锯战。根因：**Clash Verge 把组选择持久化在 `profiles.yaml` 的 `selected` 段和 `cache.db`（bbolt 格式，改不动）里，每次它同步自己的状态就把你手改的值覆盖掉。**

最终解法（需重启 Clash，断网 2–3 秒）：

1. `profiles/Merge.yaml` → `profile.store-selected: false`（不再持久化选择）
2. `profiles.yaml` 当前 profile 的 `selected` → 改成本地最优节点
3. `config.yaml` → `mode: rule`
4. 重启

纯净验证（停掉守护 100 秒，无任何干预）：`mode` 保持 rule、`GLOBAL` 保持日本05、出口始终 JP。**根治。**

## 踩过的坑（每个都值得记）

### `speed.cloudflare.com/__up` 会整条线路 RST

2026-10-30 晚上复测时，所有节点上行都返回 `0 KB/s`，curl 退出码 35（SSL connect error）。一度以为脚本坏了。

真相：**测速端点本身在那个时段不可达**，同一时刻到 chatgpt.com 是 200 / 0.42s。

解法：端点降级链 `cloudflare → httpbingo → postman-echo`，并且必须校验 `%{size_upload}`：
服务端提前返回错误码时，`speed_upload` 会虚高（因为只算已发送字节），必须确认真的发出去了 90% 以上才算有效。

### mihomo 的 PUT 成功返回 204，`is not None` 判断是错的

```python
# 错的
def set_node(group, name):
    return api(...) is not None      # 204 无 body → None → 永远 False
```

后果极其隐蔽：`apply_node` 里 `if set_node("GLOBAL", name):` 恒为假，**后面的 `set_node("Proxies", name)` 从来没执行过**。也就是说，过去所有"切换节点"操作，实际只改了 `GLOBAL`——而 rule 模式下 `GLOBAL` 根本不生效。

**这才是"明明切了日本为什么还是卡"的隐藏成因。** 正确写法：检查返回里有没有 `_error`。

### 测速期间守护会覆盖测速目标

守护每 15 秒把 `Proxies` 拉回最优节点，而测速正在逐个切换节点——两者打架，导致部分节点测出来的是"被拉回后的那个节点"的数据。

解法：`if _auto_heal and _rank and not _bench_running:` —— 测速期间不纠正节点，只纠正模式。

### Windows 批处理的编码陷阱

- 用 UTF-8 写含中文的 `.bat`，cmd（代码页 936）解析直接错乱，整段报"不是内部或外部命令"
- 转成 GBK 后**仍然乱**，典型"锟斤拷"——因为脚本里还留着 `chcp 65001`，cmd 用 UTF-8 去解 GBK 字节

正确做法：

| 场景 | 编码 | 是否写 chcp |
|---|---|---|
| bat 自身要显示中文 | GBK | **不写** |
| 纯 ASCII，靠 python 输出中文 | ASCII | 写 `chcp 65001` |

### 切节点不会迁移已有连接

通过 REST API 切换节点，实测 **22 条连接里 21 条存活**，且继续走在旧节点上。

意味着：切了节点之后，正在跑的大上传还赖在慢节点上，新请求才走新节点。这就是"切了还是慢"的原因。想彻底换，只能断掉那些连接（工具里的「自动统一」就是干这个）。

反过来这也是好事：**切换节点不会打断正在进行的工作**，所以测速可以放心跑。

## 最终架构

```
Clash Verge（配置层，被改造过）
  ├─ store-selected: false    ← 不记忆选择，避免回滚
  ├─ mode: rule               ← 国内/内网直连，不占隧道
  └─ 节点由 clash-opt 接管

clash-opt（常驻进程，Python 标准库 + curl，无第三方依赖）
  ├─ 采集   1 秒    上下行、连接数、隧道承载、滞留连接
  ├─ 体检   15 秒   模式/节点校验（被打回就拉回）
  ├─ 探测   60 秒   到 chatgpt.com 的首字节
  ├─ 测速   45 分钟 30 个候选节点，按上行排序
  └─ 看板   8787    单文件 HTML，1.5 秒轮询
```

### 三个自动开关（都在看板上，默认全开）

| 开关 | 作用 |
|---|---|
| 纠正 | 模式/节点被打回，15 秒内拉回 |
| 优选 | 按上行实测挑最优（不是按延迟） |
| 统一 | 有连接赖在慢节点上且还在传数据，切回并断掉它重连（10 分钟限频） |

## 一条没走通的路

考虑过直接把功能做进 Clash Verge 的原生界面（改 Rust + 前端源码）。

放弃理由：

1. 要维护 fork，Verge 每次升级、机场订阅格式变化都要重新合
2. Tauri 打包需要 Rust 工具链 + Node + VS Build Tools，改个按钮代价太大
3. **核心问题不在界面层**——"节点被改回""香港上行被限""AnyTLS 队头阻塞"这三件改 UI 一件都解决不了
4. Clash Verge 自己的界面本身就是 HTML（Tauri webview），"避免 HTML"这个目标在技术上不成立

折中：把看板注册进 `verge.yaml` 的 `web_ui_list`，从 Clash Verge 里就能打开，等于一个入口。

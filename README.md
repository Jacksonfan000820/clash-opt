# clash-opt · Clash 代理链路监控与自愈

> ## ⚠️ 新机器拉下来，先跑这两条
>
> ```bash
> python3 clash_opt.py check    # 自检：Clash 起没起、配置对不对
> python3 clash_opt.py fix      # 一键修好（会改 Clash Verge 的配置）
> ```
>
> **然后重启一次 Clash Verge**（会断网 2–3 秒）。
>
> 不做这一步的后果：Clash Verge 会周期性把选好的节点改回它记住的那个，
> 本工具每 15 秒拉回来一次，形成拉锯战 —— 功能能用，但每次都有十几秒空窗。
>
> macOS 用户可以直接双击 `首次配置.command`，等同于上面两条加提示。

给「Codex 生图卡」这一类问题做的工具。它不只是看延迟——**延迟正常但上行被打死，才是这类卡顿的典型形态**。

## 为什么需要它

三件事决定了不能靠手动调：

1. **选节点会被写回。** Clash Verge 把当前选择存在 `profiles.yaml` 的 `selected` 段和 `cache.db` 里。你在界面上点一下、或者它自己同步一次，手动改的文件就被覆盖回去了。实测：改完 9 小时，`mode` 和 `Proxies` 全部回滚。
2. **看延迟挑不出好节点。** 香港 20~30ms、日本 82ms，按延迟必定选香港；但香港上行只有 400 KB/s 左右，日本有 2000~2800 KB/s。**延迟和上行是两件独立的事。**
3. **AnyTLS 是单隧道多路复用。** 一个连接上去挂住，同一条隧道上的所有请求一起排队。所以某个节点上行被打死时，表现不是「某个请求慢」，而是「Codex 整个界面卡住」。

## 用法

双击 `启动看板.bat`，或者：

```bash
python -X utf8 clash_opt.py serve        # 常驻：采集 + 自愈 + 看板
```

浏览器打开 <http://127.0.0.1:8787>

其他命令：

```bash
python -X utf8 clash_opt.py status       # 一次性状态快照
python -X utf8 clash_opt.py diag         # 诊断卡在网络还是卡在客户端
python -X utf8 clash_opt.py bench        # 实测 30 个候选节点上行并排名
python -X utf8 clash_opt.py apply 日本02  # 手动固定节点（自动切 rule 模式）
```

## 它替你做的四件事

| 行为 | 频率 | 说明 |
|---|---|---|
| 采集吞吐 | 1 秒 | 上下行速率、活跃连接、隧道承载分布 |
| 体检 | 60 秒 | 到 chatgpt.com 的首字节时间，2 次连续异常触发自动换节点 |
| 纠正 | 60 秒 | 模式被改回 `global`、或 Proxies 组被换掉，自动拉回来 |
| 重测 | 45 分钟 | 机场调度会变，节点排名会失效，定期重新实测 |
| 自动统一 | 检测到即处理 | 有连接赖在比最优慢 3 倍以上的节点上、且还在传数据，就切回最优并清掉那条连接（10 分钟限频） |

看板右上角「自动模式」是总开关，一关全部退回手动；开启时纠正 / 优选 / 统一三项全自动。

首次启动如果没有缓存，会先跑一轮全量测速（约 2.5 分钟）。结果缓存在 `last_rank.json`，30 分钟内复用，不会每次启动都测。

## 策略

- **默认按上行实测排序**，地区只作为得分接近时的加权（香港 > 日本 > 新加坡）。
- 上行充足时，香港会自然胜出（延迟低）；香港上行被限时，自动落到日本。
- 健康分低于阈值会提示，页面上直接显示原因。

## 几个已知事实（实测记录）

- 测速端点 `speed.cloudflare.com/__up` 会在某些时段被整条线路 RST（SSL 握手就失败），工具会自动降级到 `httpbingo.org` / `postman-echo.com`。
- 通过 REST API 切节点/切模式**不会断开已有连接**，所以测速和纠正是安全的；只有 Verge 界面操作（`auto_close_connection: true`）才会主动掐连接。
- 伪节点「当前流量：xxxG / 400.00G」「到期时间：xxx」会被当成真节点出现在组里，误选就等于断网。工具会自动排除。

## 日常怎么用

**什么都不用做。** 开机登录后：

1. Clash Verge 自动启动（静默到托盘，不弹窗）
2. `clash-opt` 跟进启动，接管节点选择
3. 想看一眼就开 <http://127.0.0.1:8787>

关机就正常关，不用先关任何东西。

三个按钮：

| 文件 | 用途 |
|---|---|
| `启动看板.bat` | 手动启动监控并打开看板（已在跑就直接开页面） |
| `一键自检.bat` | 出问题时双击它，一句话告诉你卡在网络还是卡在客户端 |
| `开机自启设置.bat` | 启用 / 停用 / 立即启动 / 打开看板 |

## 开机自启

已装好：启动文件夹（`shell:startup`）里的 `clash-opt.bat`，登录后约 12 秒自动运行，无窗口、不弹黑框。

要调整就双击 `开机自启设置.bat` —— 可启用 / 停用 / 立即启动一次 / 直接打开看板。

不想自启就把启动文件夹里的 `clash-opt.bat` 删掉。

## 换电脑 / 备份

这是个可以直接推到 GitHub 的仓库。`.gitignore` 已排除运行时缓存和日志，
两台机器各自测速、互不污染。

macOS 上需要额外做的四步见 [docs/跨平台部署.md](docs/跨平台部署.md)，
核心是：关掉 `store-selected`、模式设 `rule`、`python3 clash_opt.py serve`、launchd 自启。

改代码前建议先读 [docs/改造记录.md](docs/改造记录.md)，里面记了几个
看起来能跑、实际是错的地方（比如 mihomo 的 204 响应判断）。

## 说明

个人自用工具，公开出来供参考。仓库里**不含任何机场订阅、节点地址或密钥**——
secret 是运行时从本地 `clash-verge.yaml` 读取的，测速数据存在本地且已 gitignore。

它能做的：按**上行实测**而不是延迟挑节点、守护配置不被客户端改回、
清理赖在慢节点上的旧连接、单文件 HTML 看板。

它不能做的：替你解决机场本身限速。如果所有节点一起变慢，那是上游的问题，
工具只能如实测出来并告诉你，切哪个都一样。

没有 Clash Verge 环境也能跑起来看界面，只是没有数据。
